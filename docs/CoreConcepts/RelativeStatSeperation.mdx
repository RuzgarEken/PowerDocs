# Relative Stats for Target Stats and Attribute Stats

You can find a video tutorial [▶ here](https://youtu.be/0vtKy50Hpyo). 

A Stat can participate in an Effect in two different roles:

- As the **Target Stat**, whose value will be modified.
- As an **Attribute Stat**, whose value is used by a Processor while processing an Effect.

These two roles often require different Relative Stats.

For example, consider the following scenarios:

Assume the <PowerRef kind="stat">Attack</PowerRef> Stat has two different Modifier Relative Stats, each designed for a different usage:

- <PowerRef kind="stat">AttackModifier</PowerRef> — modifies values when **Attack** is the Target Stat.
- <PowerRef kind="stat">AttackDamageModifier</PowerRef> — modifies outgoing Effects when **Attack** is used as an Attribute Stat.

<StatExample
  name="Attack"
  default={10}
  relations={[
    {key: 'Modifier_Given', value: 'AttackModifier'},
    {key: 'Modifier_Given_AttributeStat', value: 'AttackDamageModifier'},
  ]}
/>

Both modifiers increase values by **10%**, but they serve different purposes and are resolved through different Relative Stat keys.

**1. Attack Stat as the Target Stat**

The **BSModifier** Processor uses the Attack Stat as the **Target Stat**. It resolves the **Modifier_Given** Relative Stat, which points to **AttackModifier**, and increases the incoming value from **5** to **5.5** before applying it to the Attack Stat.

  </SpecCard>
  <SpecCard kind="stat" name="Attack">
    <SpecRow label="Value">10 → 15.5</SpecRow>
  </SpecCard>
</Flow>

**2. Attack Stat as an Attribute Stat**

Now consider a different situation. The Effect targets the enemy's <PowerRef kind="stat">HealthStat</PowerRef>, while the <PowerRef kind="stat">AttackStat</PowerRef> is used only as an **Attribute Stat**.

During the **ASModifier** stage of the processing funnel, the Processor evaluates the Attribute Stats attached to the Effect. Because the Attack Stat is being used in this role, it resolves the **Modifier_Given_AttributeStat** Relative Stat, which points to **AttackDamageModifier**.

This increases the outgoing damage from **-10** to **-11** before the Effect is applied to Health.

<Flow>
  <EffectExample targetStat="Health" attributeStat="Attack" value={-10} />
  <SpecCard kind="processor" name="ASModifier">
    <SpecRow label="Resolves" icon="key">Modifier_Given_AttributeStat</SpecRow>
  </SpecCard>
  <SpecCard kind="stat" name="Health">
    <SpecRow label="Value">100 → 89</SpecRow>
  </SpecCard>
</Flow>

:::warning
**The role of a Stat determines which Relative Stat relationship should be resolved.**

**Modifier_Given** is scoped to direct **Target Stat** modification. In scenario 1, **BSModifier** resolves this key and follows the relationship to **AttackModifier**.

When **Attack** is used as an **Attribute Stat**, it should not reuse **Modifier_Given**. Instead, **ASModifier** resolves **Modifier_Given_AttributeStat**, which points to the separate **AttackDamageModifier** Stat.

This separation is intentional. **AttackModifier** controls modifications to the Attack Stat itself, while **AttackDamageModifier** controls modifications to Effects that use Attack as an Attribute Stat.
:::

As shown in the samples, you will often see both **Modifier_Given** and **Modifier_Given_AttributeStat** Relative Keys.

- **Modifier_Given** is resolved by **BSModifier** when the Stat is used as the **Target Stat**.
- **Modifier_Given_AttributeStat** is resolved by **ASModifier** when the same Stat is used as an **Attribute Stat** to modify the Effect value.
